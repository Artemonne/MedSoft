# ЛР2 MedSoft: запуск и демонстрация

Это руководство описывает учебный локальный стенд с ИСУ ID `370553`. Закрытые ключи, пароли,
bootstrap-секрет и токены не должны копироваться в отчёт, Git или логи.

## Подготовка и запуск

Требуются Node.js 20.19+, npm, PostgreSQL и OpenSSL. После клонирования проекта:

```powershell
npm install
Copy-Item backend\.env.example backend\.env
```

Укажите в `backend\.env` отдельную PostgreSQL-базу в `DATABASE_URL`, затем примените миграции:

```powershell
npm exec --workspace backend -- prisma migrate deploy
```

Пользовательскую базу нельзя очищать или сбрасывать ради запуска. Миграции добавляют сущности
безопасности и сохраняют `MedicalRecord`/`MedicalRecordEvent` ЛР1.

Создайте локальные криптографические материалы и одноразовый bootstrap-секрет:

```powershell
npm run certs:generate
npm run jwt:generate
npm run admin-bootstrap:generate
```

Скрипт сертификатов использует RSA-3072, SHA-384, шифрование закрытого ключа CA AES-256-CBC и
ИСУ ID `370553`. JWT подписываются отдельной парой Ed25519 (EdDSA). Все сгенерированные файлы
находятся в игнорируемом `certificates\local` с ACL текущего пользователя. Сохраните показанный
bootstrap-секрет в менеджере секретов: приложение хранит только его SHA-256-хэш и удаляет файл
хэша после успешной настройки.

Установите доверие только к открытому корневому сертификату:

```powershell
Import-Certificate `
  -FilePath .\certificates\local\ca.cert.pem `
  -CertStoreLocation Cert:\CurrentUser\Root
```

Перезапустите браузер, запустите приложение и откройте `https://localhost:5173`:

```powershell
npm run dev
```

Браузер устанавливает TLS 1.3 с Vite, а Vite устанавливает независимо проверяемое TLS 1.3
соединение с Express API на `https://localhost:3001`. HTTP downgrade отсутствует. Подробности и
удаление учебного CA из хранилища Windows приведены в [tls.md](tls.md).

## Первоначальная настройка администратора

1. Откройте `/admin/setup` и введите одноразовый bootstrap-секрет, пароль и подтверждение.
2. Отсканируйте QR-код приложением-аутентификатором либо введите Base32-строку вручную.
3. Введите текущий шестизначный код. До его проверки настройка не завершена.
4. После завершения секрет TOTP больше не выдаётся, повторный bootstrap запрещён.
5. Для входа на `/admin/login` всегда нужны пароль и актуальный TOTP-код.

TOTP соответствует RFC 6238: HMAC-SHA-1, 6 цифр, шаг 30 секунд, окно ±1 шаг. Механизм
восстановления TOTP по условиям работы отсутствует.

## Аккаунт медработника

Администратор создаёт медработника в разделе «Медработники», затем в разделе «Аккаунты» задаёт
уникальный username и связывает аккаунт с этим работником. Система показывает случайный пароль
ровно один раз. Он состоит из 12 латинских букв обоих регистров и цифр; сохраните его до закрытия
диалога. В БД попадает только scrypt-хэш с отдельной 128-битной солью.

Администратор может заменить пароль, деактивировать/активировать аккаунт и изменить роль. Замена
пароля, деактивация и смена роли атомарно отзывают активные refresh-сессии. Логическое удаление
медработника также деактивирует связанный аккаунт.

## Права ролей

| Действие | doctor | nurse | laboratory-technician | other |
| --- | --- | --- | --- | --- |
| Просмотр пациентов, диагнозов, ЭМК и истории | да | да | да | да |
| Создание/изменение пациента и создание ЭМК | да | да | нет | нет |
| Разблокировка ЭМК | да | нет | нет | нет |
| Изменение разблокированной ЭМК | да | да | нет | нет |
| Изменение справочника диагнозов, удаление пациента | да | нет | нет | нет |

Идентификатор автора и актуальная роль загружаются сервером из проверенной сессии и БД.
`workerId` клиента не используется. Административные маршруты принимают только отдельный тип
администраторского JWT.

## JWT, refresh и аудит

Access JWT живёт по умолчанию 15 минут и хранится фронтендом только в памяти. Refresh JWT живёт
7 дней, передаётся только в `Secure; HttpOnly; SameSite=Strict` cookie, а запросы refresh/logout
требуют CSRF-заголовок. Refresh хранится в БД только как SHA-256 проверочный хэш. Каждая ротация
атомарно выдаёт новую пару, отзывает предшественника и пресекает повторное или конкурентное
использование.

`AuditEvent` — неизменяемый журнал безопасности, отдельный от истории версий ЭМК
`MedicalRecordEvent`. Его видит только администратор. Экран опрашивает сервер раз в секунду,
использует устойчивый cursor и явно показывает потерю актуальности при ошибке. В аудит не попадают
пароли, хэши паролей, TOTP-секреты, JWT, refresh-токены и клиническое содержимое ЭМК.

## Проверка TLS и тесты

Статическая проверка цепочки, назначений и полей сертификатов:

```powershell
npm run certs:verify
```

При работающем backend успешный TLS 1.3 handshake:

```powershell
openssl s_client -connect localhost:3001 -servername localhost `
  -CAfile certificates\local\ca.cert.pem -verify_return_error -tls1_3
```

Та же команда без `-CAfile` должна завершиться ошибкой доверия, а вариант с `-tls1_2` — ошибкой
версии протокола. Нельзя применять `-k`, `rejectUnauthorized: false` или
`NODE_TLS_REJECT_UNAUTHORIZED=0`.

Полный набор автоматических проверок:

```powershell
npm run prisma:validate
npm run prisma:generate
npm run typecheck
npm run build
npm test
```

Integration-тесты выполняйте только на отдельной мигрированной тестовой БД, передав ей
`DATABASE_URL`. Они создают и удаляют тестовые строки.

## Сценарий защиты

1. Показать `npm run certs:verify`, Subject/Issuer/SAN и успешный TLS 1.3 handshake; затем отказ
   без CA и отказ TLS 1.2.
2. Запустить приложение, выполнить защищённый bootstrap и подтвердить TOTP.
3. Войти администратором, создать медработника и аккаунт, сохранить одноразово показанный пароль.
4. Войти как doctor, создать пациента и ЭМК, разблокировать её, добавить диагноз/назначение.
5. Показать реального автора события, версии и восстановление ЭМК на дату/время.
6. Войти как nurse и показать создание пациента/ЭМК без права разблокировки; для
   laboratory-technician/other показать режим чтения.
7. Изменить роль или деактивировать аккаунт и показать немедленную потерю старых привилегий.
8. Открыть аудит, показать появление событий не позднее двух секунд и отсутствие операций
   редактирования/удаления.
9. Завершить демонстрацию полным запуском typecheck, build и тестов.

## Ограничения учебного стенда

- CA является учебным и устанавливается вручную; для production нужен управляемый PKI/ACME.
- Закрытые ключи защищены локальной ACL, но не HSM или внешним менеджером секретов.
- Rate limiter хранится в памяти одного процесса и сбрасывается при перезапуске.
- Обновление аудита реализовано polling раз в секунду, а не push-каналом.
- Восстановление TOTP намеренно не реализовано по условию задания.
- Прямое сравнение с исходным файлом «Лабораторная 2.pdf» не выполнено: файл не был доступен;
  проверены все требования из переданного текста задания.
